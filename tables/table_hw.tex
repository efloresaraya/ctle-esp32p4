\smallskip
\begin{minipage}{\textwidth}
  \footnotesize
  \textbf{Prefill coherence.}
  For all three methods, prefill\,ms/tok $\approx$ gen\,ms/tok (deviation $<$2\,\%),
  confirming that a single transformer forward pass dominates latency and that KV-cache
  growth over 64 generated tokens is negligible.

  \textbf{INT4BW overhead.}
  Despite an identical 4-bit weight budget (after rounding), INT4BW is
  \textbf{31\,\%} slower than both INT4U and CTLE (1{,}356 vs.\ 1{,}038\,ms/tok).
  The root cause is the per-group scale table \texttt{scales[rows $\times$ $\lceil$cols/$G\rceil$]}
  stored in PSRAM: with $G{=}32$ and $N{=}288$ columns, each matvec row requires
  $\lceil 288/32 \rceil = 9$ additional PSRAM scale reads, doubling effective memory
  traffic.  INT4U (single tensor scale) and CTLE (16-float LUT resident in
  registers during the row loop) avoid this overhead entirely.

  \textbf{PSRAM watermark.}
  The minimum-free-PSRAM watermark equals the steady-state free value for all methods,
  confirming no transient allocations occur during inference.

  \textbf{SRAM.}
  Internal SRAM (624\,KB total) remains 570\,KB free throughout inference.
  The 54\,KB used by the IDF runtime (stacks, USB, logging) leaves ample headroom for
  the activation buffers already embedded in the PSRAM-allocated \texttt{RunState} struct.
\end{minipage}
